# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

В проекте используются 2 интерфейса для представления данных о товаре и покупателе и 3 класса для хранения и работы с данными

#### Интерфейс IProduct

interface IProduct {
id: string;
description: string;
image: string;
title: string;
category: string;
price: number | null;
}

`id` - значением является строка, содержащая id товара
`description` - значением является описание товара представленное в виде строки
`image` - значением картинка товара. Она представлена в виде пути до картинки, строкой
`title` - значением ключа является название товара
`category` - значением является к какой группе пренадлежит товар
`price` - цена товара, приналичие цены товара представлена числом и при отсутствии товара цены товара принимает значение null

#### Интерфейс IBuyer

interface IBuyer {
payment: TPayment | null;
email: string;
phone: string;
address: string;
}

`payment` - значением будет являть строки: 'card' | 'cash', обозначающие выбранный способ оплаты, либо его отсутствие null
`email` - принимает строку адресс электронной почты покупателя
`phone` - принимает строку номера телефона покупателя
`address` - принимает строку адресса покупателя

#### Класс Catalog

Используется для учета данных. Он хранит массив всех товаров и позволяет их получать и искать выбранный товар по его id, а так же хранит данные по выбранному товару, для подробного отображения.

Конструктор:  
`constructor(protected event: IEvents)` - принимает брокер событий

Поля класса:
`products: IProduct[] = []` - Массив товаров. Хранит массив товаров пришедший с сервера. Массив состоит из объектов, соответствующих интерфейсу IProduct.
`selectedProduct: IProduct | null = null` - Хранит выбранный, для подробного описания товар, представляющий собой объект интерфейса IProduct или null.

Методы класса:
`setProducts(products: IProduct[]): void ` - сохранение списка товаров. Принимает массив товаров и сохраняет его поверхностную копию в значение поля products. Эмитит событие "catalog:products-updated"
`getProducts():  IProduct[]` - получение списка товаров. Возвращает массив товаров из поля products
`getProductById(id: string): IProduct | undefined ` - получение товра по его идентификатору. Принимает id товара и ищет соответствующий товар в массиве из поля products. Возвращает найденный товар или undefined
`setSelectedProduct(selectProduct: IProduct | null): void` - сохранение выбранного товара. Принимает товар как объект интерфейса IProduct, ищет его в маасива товаров поля products и сохраняет в поле selectedProduct, если товар не был указан или был не найден, присваивает полю selectedProduct значение null. Эмитит событие "catalog:selected-product-changed"
`getSelectedProduct(): IProduct | null` - получение выбранного товара. Возвращает значение поля selectedProduct

#### Класс Basket

Реализует логику работы корзины приложения. Отвечает за хранение товаров в корзине, их получения и управление составом корзины.
Конструктор:
`constructor(protected event: IEvents)` - принимает брокер событий

Полe класса:
`products: IProduct[] = []` - товары расположенные в корзине. Массив товаров, состоящий из объетов интерфейса IProduct[]

Методы класса:
`getProducts(): IProduct[]` - Получение товаров корзины. Возвращает массив товаров из поля products
`addProduct(item: IProduct): void` - Добавление товара в корзину. Принимает товар и добавляет его в массив товаров из поля products. Эмитит событие "basket:changed".
`deleteProduct(item: IProduct): void ` - Удаление товара из корзины. Принимает товар, фильтрует массиов товаров, оставляя только те товары id которых не равен id принимаего товара. Эмитит событие "basket:changed"
`clear(): void` - очистка корзины. Меняет значения поля products на пустой массив. Эмитит событие "basket:changed"
`getTotalaPrice(): number` - Получение суммы стоимости товаров в корзине. Создается переменная суммы. Перебераются товары в корзине и если их стоимость не равна null, то она прибавляется к перенной суммы. Возвращает сумму стоимости всех товаров
`getCount(): number` - Получение количества товаров в корзине. Переменной количества товаров присваивается значение длинны массива из поля products. И возвращается это значение
`hasProductById(id: string): boolean` - Проверка наличия товара в корзине. Принимает товар и ищет его в массиве, евли находит возвращается true, если не находит возвращается false

#### Класс Buyer

Класс для хранения и валидации данных пользователя-покупателя.
Конструктор:
`constructor(protected event: IEvents)` - принимает брокер событий

Поля метода:
`payment: TPayment | null = null` - значением будет являть строки: 'card' | 'cash' | null, обозначающие выбранный способ оплаты, либо его отсутствие
`email: string = '';` - принимает строку адресс электронной почты покупателя
`phone: string = ''` - принимает строку номера телефона покупателя
`address: string = ''` - принимает строку адресса покупателя

Методы класса:
`setPayment(payment: TPayment): void` - Сохранение выбранного типа оплаты. Принимает значение выбранного типа оплаты. Эмитит события "buyer:changed" и "buyer:set-payment"
`setEmail(email: string): void` - Сохранение адреса электронной почты покупателя. Принимает адресс электронной почты и сохраняет его в поле email. Эмитит событие "buyer:changed"
`setPhone(phone: string): void` - Сохранение номера телефона покупателя. Принимает номер телефона и сохраняет его в поле phone. Эмитит событие "buyer:changed"
`setAddress(address: string): void` - Сохранение адреса покупателя. Принимает адресс и сохраняет его в поле address. Эмитит событие "buyer:changed"
`getBuyer(): IBuyer` - Получение данных о покупателе. Возвращает объект данных о покупатели из полей класса с интерфейсом IBuyer
`clear(): void` - Очистка данных покупателя. Очищает значение всех полей. Эмитит событие "buyer:changed"
`validate(): IBuyerErrors` - Валидация данных пользователя. Создает пустой Объект ошибки. Кючами является названия полей, значениями - сообщения об ошибке. Проверяет каждое поля на присутсвтвие значение и если его нет, то добавляет в объект пару ключ: значение. Возвращает объект ошибки, если он пустой, данные считаются валидными.

### Слой коммуникации

#### Класс LarekApi

"Слой-коммуникатор" с сервером. Отвечает за получение данных о товарах с сервера и отправки данных о покупке на сервер

Конструктор `constructor(api: IApi) ` принимает экземпляр низкоуровневого API‑клиента типа IApi

Поле класса:
`api: IApi` - Низкоуровневый клиент для выполнения запросов

Метод класса:
`async getProductList(): Promise<IProductListResponse>` - Получение списка товаров с сервера. Использует метод get() из класса Api. Принимает в его параметры эндпоинт /product/ и возвращает ассинхронный ответ с данными товаров
`async createOrder(order: IOrder): Promise<IOrderResponse>` - Отправка информации о покупке на сервер. Принимает данные о заказе в виде объекта. Использует метод post() класса Api и возвращает ассинхронный ответ сервера о заказе.

Конструктор:  
`constructor(protected event: IEvents, container: HTMLElement,)` - принимает брокер событий и ссылку на DOM элемент за отображение, которого он отвечает. Находит и сохраняем все элементы, с которыми будет работать компонент. Добавляет обработчик событий на кнопку и вне модального окна и емитим событие "modal:close"

для каждого товара клонирует шаблон карточки;
инициализирует компонент CardByCatalog;

Инициирует отправку данных заказа на сервер, а при успехе — отображение экрана «Заказ успешно оформлен» и очистку корзины и данных покупателя.

Поведение обработчика:
Сбор данных покупателя. Вызывается buyerModal.getBuyer() для получения объекта IBuyer.
Формирование списка ID товаров. Из корзины извлекаются товары, из них собираются только id в массив ItemsIds.
Создание объекта заказа. Через Object.assign формируется IOrder, объединяющий данные покупателя, итоговую сумму (basket.getTotalaPrice()) и список ID товаров.
Асинхронная отправка заказа. Вызывается server.createOrder(order).
Обработка успешного ответа:
находится шаблон #success;
клонируется его содержимое;
создаётся экземпляр SuccessOrder;
устанавливается цена заказа из ответа сервера;
форма успеха помещается в модальное окно и рендерится;
сбрасываются корзина и данные покупателя.
Обработка ошибок. При ошибке отправки логируется сообщение, UI не меняется.

#### Событие "success:close"

Инициирует закрытие модального окна с экраном успеха после оформления заказа

Поведение обработчика:
Изменение состояния. Устанавливается modal.modalISActive = false
